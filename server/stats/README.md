# 匿名统计：跨设备 match_id 去重升级

## 标识约定

- 客户端本地 `matches.match_id`：SQLite 自增整数，旧版关联表和页面路由继续使用，允许不同电脑不一致。
- WebDAV `uid` = 客户端 `sync_uid` = 匿名统计 `match_id`：同一个 32 位稳定标识，跨设备相同，不包含游戏名或游戏 ID。新字段可能让统计服务识别出两台匿名设备发送了同一局，隐私说明已更新。
- 匿名统计 `k`：保留旧的 `sha256(匿名编号|本地局号|时间)` 前 20 位，用于匹配历史行和旧客户端；它不是跨设备去重键。

服务器的 `matches.match_id` 是可空文本。非空值有唯一索引，同一局即使来自不同匿名编号也只保留一行。老客户端没有这个字段时仍按 `(id,k)` 接收。`match_keys` 保存已升级设备的旧键别名，使降回旧客户端后的重发仍能找到原来的全局记录。

一批上报中的别名写入、旧重复行删除和记录覆盖一起放在 D1 `batch` 事务中，失败共同回滚。新的全局记录保留最早接收时的匿名编号作为汇总归属，服务端 `k` 使用 `uid:<match_id>` 的独立命名空间，设备内旧 `k` 保存在别名表。这样复制过匿名编号的两台电脑，即使旧 `id/k` 完全相同但 UID 不同，也不会把不同对局覆盖成一局。日活仍按设备统计。同一局的统计数值采用最后收到的上报，而非 WebDAV 的逻辑版本比较。

## 部署顺序（由拥有统计服务权限的维护者执行）

先在本机运行测试，再备份、迁移已有库，最后部署 Worker。迁移前请保留旧 Worker 代码和数据库备份。

```text
python tests/test_telemetry.py
python tests/test_stats_worker.py
cd server/stats
wrangler d1 export evo-stats --remote --output before-match-id.sql
wrangler d1 execute evo-stats --remote --file add_match_id.sql
wrangler deploy
```

`add_match_id.sql` 只对已经有 `matches` / `summary` 的现有统计库执行一次，新增可空列、唯一索引和别名表，不删除旧对局。再次执行 `ALTER` 会报告重复列，不是幂等迁移。新建库直接运行 `schema.sql`，不要再执行 `add_match_id.sql`。不能先部署新 Worker 再加表列；恢复旧 Worker 可继续使用迁移后的附加结构，但旧 Worker 不提供跨设备去重。

部署后服务端在 `/v1/report` 成功响应中返回 `match_id_version: 1`。可以使用独立测试环境上报两份 `match_id` 相同、`id/k` 不同的合成对局，确认 `matches` 中只有一行。不要向生产统计写入测试对局。生产迁移和部署不会由客户端更新自动执行。

客户端先连到旧服务时，新字段会被忽略，不能宣称已经去重。后续发送或日活一旦收到新能力确认，客户端会清空旧发送缓存，下次补报符合原有同意时间范围的记录；不突破用户的同意边界。未上报、未收到服务升级确认时，仍可能暂时有旧重复行。

## 历史数据与兼容边界

设备补报 `(id,k,match_id)` 时：删除该设备内的旧无身份行，再按 UID 写入或更新全局行，保持原始全局所有者；这两个步骤与别名写入在同一事务中。后续旧客户端的同键上报通过别名归并，不再新建无身份副本。如果同一旧 `id/k` 已对应多个不同 UID，别名记为空字符串表示歧义；新的带稳定 ID 上报仍正常接收，未带稳定 ID 的旧格式会拒绝计入 `rejected`，不会猜测覆盖某一局或生成新的无身份重复行。旧客户端遇到这种情况应升级。

无法从旧的匿名 `k` 反推跨设备身份。已经卸载或不再上报的设备、同意范围之外的旧记录，没有可靠稳定 ID 时不能盲目合并。服务器不会按伤害、日期或阵容相似就删除记录，避免把不同人的对局误合并。删除接口仍按原来的匿名编号删除其所有行，同时清理该编号的别名；由另一设备先建立的共享全局行仍属于那个设备，之后仍可由它上报。

迁移会清空缓存汇总，使下一次访问重新计算；后续上报后的汇总刷新仍沿用现有每小时任务与 HTTP 缓存周期。

测试使用支持 `node:sqlite` 的 Node（本机验证为 Node 24）运行真实 Worker 和真实 SQLite，并用轻量适配器模拟 D1 API；不安装新的生产依赖。缺少 Node 或 `node:sqlite` 时全量测试明确跳过该组，不能据此宣称服务端测试通过。测试覆盖新建/历史库迁移、跨设备重复、旧格式重发、编辑、误合并防护、事务回滚、删除与真实汇总接口，以及真实 WebDAV 同步产生的 Python 载荷。

事务与唯一约束语义参考 [D1 batch](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch) 和 [SQLite UPSERT](https://www.sqlite.org/lang_upsert.html)。
