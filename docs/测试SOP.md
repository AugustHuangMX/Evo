# 测试 SOP

什么时候跑哪些测试（2026-11-04 用户定的）。测试是为了确认没改坏：按改动的范围跑，不多跑，也不少跑。

## 三种情况

### 不跑

- 只改文档、注释、待办：`docs/`、`claude/`、CLAUDE.md、`release/` 里的文字，代码里的说明和注释
- 改官网（`site/`）、宣传图：这些不在测试里，打开看效果
- 例外：加、删、改名了文件，或者改了文件开头说明的第一句，要重新生成代码地图（`python tools/code_map.py`），再跑 `python tests/test_code_map.py`（几秒）

### 只跑相关的一两组（几秒到一两分钟）

- 改了页面、底座（托盘、窗口、更新、设置、数据文件夹……）、测试工具、开发脚本：跑测这个功能的那一组
- 哪一组测它：在 [代码地图](代码地图.md) 的"测试（tests/）"一节搜改的文件名（每个测试文件那一行写着它测哪些文件）；也可以搜 `tests/` 里谁 import 了这个模块
- 单独跑一组：`python tests/test_sounds.py`（换成那一组的文件名）
- 没有测试管到的改动：写清楚是怎么验证的（打开页面看了、运行了一次脚本……）

### 跑全部（`python tests/run_all.py`，约 9–11 分钟）

- 改了模型：识别（代码地图"模型"一节里的文件）、`config/` 里的规则、记录程序（`live_collect.py`、`in_match.py`、`post_match.py`、`calibration.py`）。牵一发动全身，只有一局从头到尾的重放测试才看得出来
- 改了数据库 `storage.py`：几乎每一组都用到它
- 新赛季游戏更新以后
- 发新版本：`tools/release.py` 自己会先跑全部，没通过不打包，不用另外跑
- 放在后台跑，同时可以做别的；跑完看最后的"结果"表

拿不准算哪一种时，往多跑一档（比如不确定会不会影响记录程序，就跑全部）。

## 跑完以后

- 全部 ✅ 才算没改坏。"⏭ 跳过"是找不到截图（截图只在开发者电脑的 `captures/` 里），不算通过，要说出来
- 有 ❌：先修好再提交。不改测试里的正确答案去迁就代码，除非确认原来的答案错了，并告诉用户
- 提交说明的"怎么验证的"里写跑了哪几组、结果怎样

## 测试是怎么做的

- `tests/fake_game.py` 用"假摄像头"把真实截图按顺序喂给记录程序，数据写进临时文件夹（不碰正式数据），时钟是假的。正确答案写在 `tests/` 里的 CSV 和测试文件里
- 每一组是一个 `tests/test_*.py`，有一个 `main()`：返回 True（通过）、False（没通过）、None（跳过）。新加的组要加进 `run_all.py` 的 `TESTS`
- 测试只 import 项目代码，项目代码不能 import 测试（否则 PyInstaller 会把测试打进安装包）。要用 `tools/` 里的脚本时，用 subprocess 运行它
