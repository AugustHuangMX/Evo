# 底座：截屏、库、窗口、托盘、打包、安装、发布

打包、发布、安装、改托盘或窗口时读这份。日常改模型、改页面用不到。

## 截屏和识别用的库

- 截屏：`dxcam`（DXGI）为首选，备选 `mss`（GDI，零依赖）。两者在全屏下都可用，dxcam 平均 4.6 ms、mss 28 ms。WGC（`windows-capture`）为保持轻量暂不采用
  - dxcam 0.3 要用 `processor_backend="numpy"`（默认依赖 OpenCV）；mss 10.2 用 `mss.MSS()`（旧写法 `mss.mss()` 已弃用）
  - CPU：桌面上实测，dxcam 截一张只要约 4 毫秒，但之后进程里约 15 个线程（很可能是显卡驱动的）空转约 0.1 秒，每张合计约 1.4 秒 CPU；mss 每张约 0.01 秒。截图频率对内存几乎没有影响（每 1 秒和每 0.3 秒都是约 126–136 MB）。游戏里实测（2560×1440，对局中每 0.3 秒一张）：记录子进程 CPU 平均 14–21% 个核，内存约 200–220 MB，比桌面上低得多；帧数影响还没测
- 图像处理：`opencv-python-headless`（RapidOCR 的依赖，无图形界面版；不要再装 `opencv-python`，两者会冲突）、`numpy`
- OCR（引擎）：RapidOCR 3.10 + onnxruntime 1.31。模型（PP-OCRv6 small 检测 / 识别）内置在安装包里；代码中直接指定 `model_path`，不会触发联网下载。单线程，关闭方向判断（`use_cls`）
- 各库的内存：dxcam 49 MB（含 DirectX 组件）、onnxruntime 35 MB（第一次建引擎时才加载，之后一直在）、cv2 17 MB、numpy 13 MB；识别模型约 40 MB，可以释放（`ocr.LazyEngine`：用到才加载，闲置 2 分钟释放）

## 窗口、面板、托盘

- 面板：Flask + 模板 + 纯 HTML/CSS（少量 JS），不用 React、Node.js。运行时不加载任何网络资源。端口 5000–5019（Chromium 内核会拒绝 5060 等"不安全端口"）
- 窗口：`pywebview`（BSD）+ Windows 自带的 WebView2（`app_window.py`）。去掉系统边框，自定义深色标题栏（图标、EVO、最小化 / 最大化 / 关闭）；拖动和改大小交给 Windows 原生处理（在标题栏 / 边缘按下时发 WM_NCLBUTTONDOWN）。面板网页靠 User-Agent 里的 `EvoApp/` 知道自己在窗口里。窗口打开时独占约 130 MB（Python 52 MB + WebView2 约 80 MB），关掉全部还回去。要像 Outplayed、Blitz 那样的软件窗口，不在浏览器里打开
  - 字体：数字和英文用 Chakra Petch（OFL 许可，woff2 文件放进项目），中文用系统自带的微软雅黑
- 托盘：`pystray`（LGPLv3）。右键菜单是 Windows 原生样式，不能自定义颜色。我们的代码仍是 MIT；发布 exe 时要附上 pystray 的许可证原文，并让它以普通 .py 文件的形式放在程序文件夹里（不压进程序内部），方便别人替换
- 托盘程序 `evo_app.py` 的结构：托盘进程只负责检测游戏、托盘图标和面板（约 37 MB）；检测到游戏时另开一个**记录子进程**跑 `live_collect.collect()`，游戏关掉就让它安全停下并退出，识别模型的内存全部还给系统（停下后托盘回到 37 MB）。识别模块崩溃也只影响子进程，60 秒后自动重试
- 启动行为：打开 Evo 就立刻弹出窗口（约 1 秒），不能只在托盘里，否则像没打开成功。Evo 已经在运行时再双击，就让它把窗口弹出来（Windows 命名事件），不弹"已经在运行"的提示。关掉窗口 Evo 仍在托盘里记录，第一次关时弹一条 Windows 通知说明，只提示一次（记在数据文件夹的 `settings.json`）。"只能运行一个"按数据文件夹区分
- 图标由用户设计（蓝色胶囊 + 上升柱状图），文件是 `assets/icon/evo.png`（要求见 `assets/icon/` 里的 README）；程序自动裁掉四周透明空白（`icons.py`）。托盘、exe、窗口标题栏、面板左上角的标志、浏览器标签页都用它

## 打包和安装

- 打包：`python tools/build.py`（用 `tools/evo.spec`，PyInstaller 6.22，只在开发时用）→ `dist/Evo/Evo.exe`。打成"一个文件夹"（onedir）：一个很小的启动器 `Evo.exe` + `_internal` 文件夹，不做单个 exe（启动慢、更容易被杀毒软件误报）。自己电脑上生成的 exe 不会触发 SmartScreen（只有从网上下载的才会）。不要直接运行 `dist\Evo\Evo.exe`：它开着时没法重新打包
- 安装：程序装在 `E:\Evo Tracker`，数据（数据库、截图、日志）放在 `E:\Evo Tracker Data`。`python tools/install.py "E:\Evo Tracker" --data "E:\Evo Tracker Data"`：复制程序、写 `data_location.txt`、建桌面和开始菜单快捷方式；只动程序文件，不碰数据文件夹；Evo 开着时不装（要等用户退出 Evo；安装前先备份数据库）
- 打包版找数据的顺序：环境变量 `EVO_DATA_DIR` → Evo.exe 旁边的 `data_location.txt` → `%LOCALAPPDATA%\Evo\`。配置和模型从程序所在目录读取。所有路径由 `paths.py` 统一管理，代码里不依赖"当前目录"。`EVO_CAPTURES_DIR` 单独指定截图文件夹。数据库里的截图路径存成相对于数据文件夹的写法（不在数据文件夹里的截图存完整路径）
- 用源码运行：`python code/evo_app.py` 时（`source_run.py`）战绩记进安装版的数据文件夹（启动前自动备份数据库，留最近 5 份），截图全部存进项目的 `captures/`（测试集，一张都不删）；安装版的数据文件夹在哪里由 `install.py` 写进项目里的 `installed_data_location.txt`（不提交）。所以源码版和安装版不能同时开。其他源码脚本（`panel_app.py`、`demo_data.py`、测试）用项目文件夹，`EVO_DATA_DIR` 可以指定别的数据文件夹
- 打包后排查问题：`Evo.exe --check-image 截图.png` 自检（结果写进 logs/evo.log；可以先设 `EVO_DATA_DIR` 指向临时文件夹，免得写进正式日志）；`--background` 启动时只进托盘、不弹窗口（留给开机自启）；`--no-window` 只启动面板服务（测试用）

## 一键更新（`code/updater.py`，0.3.3 起）

- 2026-10-19 用户决定：在 Evo 里下载、安装、自动重新打开。用户点"立即更新"才下载，下载完显示"安装并重新启动"，再点一次才装（原则 2）
- 下载：地址、SHA-256、大小来自 `latest.json` 的 `download`（`release.py` 写），只接受 `dl.evotracker.cn` 的 https。下载到**程序文件夹**里的 `_update/`（不在数据文件夹：不在 AppData 里运行下载的程序，杀毒软件对这个敏感；也不占系统盘），核对后解压到 `_update/<版本号>/Evo/`，写 `ready.json`。下载前检查程序文件夹能写入、空间够（压缩包的 5 倍）；装在 C:\Program Files 这类不能写的地方只能去官网
- 安装：Windows 不让覆盖正在运行的程序，所以让新版本来换。旧的 Evo 打开 `_update/<版本号>/Evo/Evo.exe --apply-update <程序文件夹> --wait-pid <自己> --from-version <旧版本>`，等它写出 `_update/started`（20 秒没写出就当作被杀毒软件拦住，旧的照常运行、提示用户），然后托盘程序自己退出。新版本等旧的退出，把要换的东西（新压缩包 `Evo/` 下的每一项 + `Evo.exe`、`_internal`）挪进 `_old_version/`，再复制新的；出错就挪回去。`data_location.txt` 和别的不认识的文件不动。结果写 `_update/result.json`，过程写 `install.log`，然后打开程序文件夹里的 Evo.exe
- 新打开的 Evo（`after_start`）读结果，写进日志、窗口顶部说一次；1 分钟后删掉 `_update/` 里装过的版本和 `_old_version/`。安装程序半路被杀掉（只有 `pending.json`、没有结果）时说"没装上"
- 另开进程（`spawn`）：独立进程（旧的退出后照样运行），去掉 PyInstaller 留下的 `_PYI_*` 环境变量并设 `PYINSTALLER_RESET_ENVIRONMENT=1`
- Apex 开着时不能安装（免得丢掉正在记录的那一局），下载可以
- 不用发布就试：把新版本的压缩包和一份 `latest.json`（`download.url` 指向本机）放进一个文件夹，`python -m http.server` 起本机服务器，用环境变量 `EVO_UPDATE_URL=http://127.0.0.1:端口/latest.json` 打开打包好的旧版 Evo（`update_check.TEST_HOST`：设了这个变量时也接受从同一个地址下载）
- 测试：`tests/test_updater.py`（本机小服务器提供假安装包；下载、核对、取消、各种出错、换文件和恢复、面板）

## 发布

- 先改 `code/storage.py` 的 `APP_VERSION`、`release/更新内容.txt`（每行一条，最多 10 条；开头写"新增：""改进：""修复："，官网更新日志页按这个分组，别的开头归到"其他"）、`release/使用说明.txt`，提交；然后：
  1. `python tools/publish.py --dry-run`：跑 `release.py`（检查提交、全部测试、打包、自检、压缩、SHA-256、写 `dist/latest.json`），预览官网要改的地方，不上传；还会打出更新日志页要加的这一版（原文）和核对码
  2. **把更新日志的原文原样发给用户，用户点头以后**（2026-10-19 用户要求）才运行 `python tools/publish.py --changelog-ok 核对码`：上传压缩包到 R2、下载回来核对 SHA-256、改官网 `site/index.html`（下载链接、版本号、大小、SHA-256）和 `site/changelog.html`（最上面加这一版，"最新"挪过来）并上传、核对线上。没确认就停在第 1 步，什么都不上传；确认以后更新内容又改过，核对码对不上也会停下。在终端里自己运行时不用加核对码，它会问 y/n
  3. `python tools/publish.py --live --yes`：最后上传 `latest.json`。它一换，开着自动检查的 Evo 就会提醒更新，收不回来，所以压缩包和官网必须先到位
  4. 在 `claude/progress.md` 的"版本"里记一笔，`git push origin main`（只推 main）
- 官网和下载都在 Cloudflare：网页是 Pages 项目 `evotracker`（evotracker.cn，"直接上传"类型，不能改成连接 GitHub；`site/` 只在本机、不进 git），下载文件在 R2 存储桶 `evotracker`（dl.evotracker.cn）。单独上传网页：`wrangler pages deploy site --project-name evotracker --branch main`。Wrangler 是 Cloudflare 的命令行工具，要 Node.js（只装在开发电脑上，不进 Evo 安装包；Evo 和面板本身不用 Node.js）
- **官网的截图不会跟着 README 换**：README 用 `docs/images/*.png`，官网用 `site/img/*.webp`。从 PNG 转：去掉最外一圈 1 像素的桌面壁纸、圆角外透明（沿用旧图的透明形状）、1262×988；换文件名，避开官网图片缓存一天，再改 `site/index.html` 的 `<img>`。`publish.py` 不管截图
- 官网更新日志页 `site/changelog.html` 由 `publish.py` 自动加新的一版（见上面第 2 步）。它靠时间线列表开头那一行和唯一一个"最新"那一版来定位，改这一页的写法时要跟着改 `publish.py`；自动加的版本没有开头那句加粗的概要（0.1.0–0.3.1 那几句是手写的）
- 改 `PRIVACY.md` 时 `site/privacy.html`（中文、英文两部分）要一起改
- 没有数字签名的 exe 可能被杀毒软件误报、被 SmartScreen 拦截（代码签名的打算见 todo.md）
