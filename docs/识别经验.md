# 识别经验：实测结论和游戏画面特征

改模型（识别逻辑、`config/`）时读这份。流程本身见 [模型流程.drawio](模型流程.drawio)，规则为什么这样定见 [对局全流程图.md](对局全流程图.md)。

坐标统一写在 **1920×1080 基准分辨率**下（`config/*.json`），运行时按实际分辨率缩放；16:10、4:3 时按游戏画面比例和每块界面贴哪条边换算（见下面"不同画面比例"）。所有区域、参照图、门槛都必须用真实截图校准。

## 实测结论

### 引擎（OCR）怎么用（最小 demo）

- 只裁小块识别，不识别整张图：整张图 1.83 秒、内存峰值 511 MB；7 个小块 0.22 秒、峰值 154 MB
- 识别小块时要设 `Det.limit_type = "max"`：默认规则会把短边放大到 736 像素，小块会被放大十几倍
- 橙色数字转灰度后再识别：彩色时 `5/7/7` 会被读成 `5/717`
- 格式校验要严格：某些预处理下 `5/7/7` 被读成 `51717`，置信度却高达 0.98
- 如果以后 OCR 准确率不够：可以考虑用数字模板匹配读数字（字体固定，快且省内存）

### 画面判断和内存

- 判断画面分两步（`screens.py`）：先把检查区域和参照图（`config/templates/`，只截关键字本身）比较文字轮廓，像了才跑识别。参照图在区域里滑动比较，能容忍关键字前面的数字、模式名长短不同造成的左右偏移。120 张截图：目标画面相似度 ≥ 0.75，其他画面 ≤ 0.19，门槛 0.35；判断结果和只用识别时完全一样
- 游戏画面上每次检查从约 215 毫秒（4 次识别）降到约 1.5 毫秒（0 次识别）。贵在"开局画面"那块：对局中左上角有很多界面文字，一次识别就要 185 毫秒
- 内存峰值的来源：识别引擎会把细长的一行字（如 464×14）拉到约 1600 像素宽再识别，一次多占约 60 MB、花 0.5 秒。所以不要让识别引擎看游戏画面。关掉 onnxruntime 的 `enable_mem_pattern` 没有用
- 没有按"大厅 / 对局中 / 阵亡 / 结算"状态限制检查哪些画面：外观检查已经很便宜，再按状态筛选省不了多少，反而可能因为状态猜错而漏掉画面

### 用户反馈"没有任何记录"时怎么查（2026-10-24）

- 那位用户（0.3.8，3840×2160，Apex 全屏 4K）的日志：两次共截屏 1.5 万张，"外观像的"只有 3 次和 0 次（开发者平时一晚上 50–2400 次）；左下角传奇（不看文字，和语言无关）第一次运行 2 小时一次都没认出，第二次 12 分钟才认出第 2 次（平时不到 1 秒）。所以最后那段对局当成靶场丢掉了
- 排除了的：**4K 本身**（2560×1440 截图放大到 4K 再认，各画面相似度几乎不变：大厅 0.95 → 0.93、头像 0.94 → 0.94）；**HDR 发白**（模拟伽马 0.5、亮度 ×2 / ×3 截断、压对比度：头像 0.77–0.94，门槛 0.5；大厅 0.85–0.95，门槛 0.35；比的是轮廓，明暗变化影响很小）
- 只是游戏语言不对（0.3.8 只认简体）时，画面认不出、但传奇照样认得出（英文截图按 0.3.8 跑：1515 张里外观像的 16 张、认出传奇 1053 张）；画面和传奇都几乎认不出，更像是**截到的不是游戏画面**：游戏在副屏（Evo 只截主显示器），或者截屏卡住
- **dxcam 0.3 拿不到新画面时**，`grab(new_frame_only=False)`（Evo 的用法）悄悄返回缓存的上一张，不报错；dxcam 自己的警告（"Output change/access loss detected"）走 `logging` 里的 `dxcam`，不进 Evo 的日志。所以在 Evo 的日志里，"截屏卡住"和"什么画面都认不出"看起来一模一样
- 光看日志分不清，所以做了诊断工具（`code/evo_diag.py`，见 `docs/底座.md`"诊断工具"）：玩家截一段发过来，`python tools/diag_report.py 压缩包` 看

### 笔记本上识别慢、提示音很久才响（2026-10-27，1diot、0010 的诊断包在 `bugs_test/`，不提交）

- **0010**（笔记本 RTX 5060 Laptop，2560×1440，游戏 2304×1440 全屏 = 16:10，自动检测读对了，画面都认得出）：只有"慢"。识别比本机慢约 11 倍（读总结页约 3 秒 / 本机 0.26，队友约 5 秒 / 0.45，经验值页 3–4 秒 / 0.31）；对局中 CPU 中位 32% 个核（用户同分辨率 16%），诊断工具只慢 1.7 倍。54 局响了"对局结束"，只有 19 局后来响了"总结页读完了"，间隔中位 23 秒（用户 8 秒）；51 次总结页有 32 次没读完就离开（用户 77 次里 12 次）。诊断那局：22:49:57 总结页出现，22:50:16 才响，22:50:17 他就离开了（在等提示音）。19 秒 = 读总结页 3 遍（第一遍名次还没滑进来，要连续两次一样）约 9 秒 + 中间插进来读刚离开的经验值页约 4 秒 + 队友 5 秒 + 名字 1 秒
- 0010 顺便发现的分局问题（还没细查）：10-25 22:22–22:23 那局（第 19 名，读数和 22:03 那局一模一样：伤害 104、RP -48，可疑）没存下；之后没认出大厅和开局画面就进了下一局，上一局淘汰画面的"第 19"混进了下一局（编号 55 名次对不上、待确认），下一局结束也没响"对局结束"（每局重新计数要等认出大厅或开局画面）
- **1diot** 主因是画面比例：游戏是 4:3 拉伸（铺满 1920×1080），可 `videoconfig.txt` 里没有分辨率（诊断信息"None×None"），"自动检测"只能当成 16:9。按 16:9 什么都认不出（诊断截图每 3 张取 1 张，共 189 张：16:9 认出传奇 0 张、总结页 0 张；4:3 认出传奇 104 张、总结页 7、经验值页 5、大厅 19），总结页只被当成"返回大厅"按钮，所以只响"对局结束"，而且每次记录只响一次；他在总结页停了 30 秒也没有第二声。10-25 自动检测的几段（16:17–17:37、20:25–20:47、21:11–21:31）结束了 7 局左右，一局都没存下（17:33 那局后来切到 4:3、靠经验值页补了名次和 RP）。他 17:37 手动选 4:3 后记录正常，20:25 又改回了自动检测
- 1diot 次因：认出来以后识别比用户的电脑慢约 15 倍：读对局中右上角 7 秒（用户 1 秒）；总结页出现到"总结页读完了"13–14 秒（用户 1–2 秒），其中读队友 7 秒（本机 0.5 秒）；4 次总结页有 2 次没读完他就离开了。记录程序做同样的事要多花 4–5 倍 CPU 时间（对局中 30–68% 个核，用户 2560×1440 才 14–18%），诊断工具（有窗口）只慢 2 倍左右
- 猜测：笔记本上 Windows 把没有窗口的后台进程放进了省电模式（EcoQoS：降频、放到小核），再加上游戏抢 CPU。本机（台式机 7800X3D）强制省电模式、开 16 个忙循环都只慢 0–30%，复现不了
- 0.4.2 带上的两项改动：读结算画面、大厅时不让 Windows 降频（`live_collect.FullSpeed`，见 `docs/底座.md`）；停在总结页时只读总结页（右上角回到大厅、下一局开局时才读，经验值页等总结页存下再读）。日志"本次记录"一行写识别平均每次几秒（用户台式机约 0.03）。看效果：`python tools/log_speed.py 旧日志 新日志`（读右上角、存总结页、存完到提示音各几秒，几次没读完就离开）

### 对局中和大厅（1080p 录像截图 `captures/samples/` + 27 张大厅截图 + 实战）

- 认得出自己的传奇 = 这一张是自己的界面：观战时左下角是被观战的人、整块往上移约 60，认不出，所以右上角只在认得出自己传奇的截图上存
- 队友的头像和自己的是同一套美术图，缩小到约 0.65 倍：传奇参照图缩小后就能认（相似度 0.80–0.83，第二像 ≤ 0.36），不用新做参照图
- 右上角每一项要单独裁一小块读（放大 3 倍、四周加边）：整块一起读时单独一个"1"会漏掉；伤害前面的图标会被读成"3""1"，要先用参照图找到图标（它和数字一起靠右对齐，位置会变），只读右边
- 右上角击杀 / 助攻 / 老板分那一行全是 0 时不显示，背后的画面会被读出一个数（实战：老板分读成 7）；那一行显示着时数字又可能读不出来（读成 0）。所以那一行看骷髅、握手图标：图标不在 = 全是 0，图标在、数字读不出来 = 留空。还没造成伤害时伤害那一格也不显示（看伤害图标）。没显示算 0 的前提：剩余小队数或 RP 读到过，证明区域没错
  - 这一行从左往右排，**数字宽度一变，后面的位置就跟着变**（2026-10-20 发现）："1"比"0"窄约 8 像素（基准），击杀是 1 时助攻、老板分整体左移，按固定位置裁就裁到了握手图标；两位数时往右移。10-18 实战里击杀、助攻读不出来、对局中偏少就是这个原因。所以先找每一项前面的图标（骷髅、握手、老板分图标，`config/templates/hud/`），再读图标右边的数字，最宽两位数，不越过下一个图标（中间有斜线、底色斜边）。16:10 那局第一次击杀以后 91 张自己的界面：90 张三项全对、1 张老板分留空、没有读错的
  - 那一行出现以后三项一直都在（老板分是 0 也显示）；用户说过老板分不是每次都有，还没见过没有的样子：老板分图标不在、这一行显示着时老板分留空，不当作 0
  - 挨打时整行变红，找图标不受影响（比的是轮廓）
- **伤害那一格靠右对齐**（2026-10-24 用英文截图发现，简体一样）：伤害到四位数时这一格往左变宽，图标从 x≈1686 移到 1675–1682，超出了原来的检查区域（1684 起），找不到图标就被当成"没显示"、记成 0。放宽到 1640–1780 后，那局 1029 → 2064 都读对了；队友的名牌盖住数字右边时那一帧留空（不会读错）。另外击杀 10 次以后骷髅图标变成带王冠的（击杀王），击杀那一行照样认得出
- **纯色的位置会比出假高分**（2026-10-24 用繁体截图发现）：比外观用的 TM_CCOEFF_NORMED 在轮廓完全是 0 的窗口（大片纯黑）上会算出 0.9、1.0：桌面上录像软件黑色的播放器，繁体淘汰画面的参照图比出 1.0（游戏开着、切到桌面时会每秒白跑一次识别）。`screens.match` 把这种位置当作不像；只在最像的位置够像（≥ 0.3）时才查它平不平，每帧只多约 0.5 毫秒。认画面、对局中的图标、传奇头像都用它
- **经验值页"下一段位"最后的段数"I"很细，常被漏掉**（2026-10-24 繁体"下個排名：白金1"读成"白金"）：以前会当成"下一段位不分段"，倒推成黄金 I（错的）。改成分段的段位读不到段数就留空（回大厅时用大厅的段位补）；繁体只框住那一行（`config/lang/zh-TW.json`）就稳定读得出
- 倒地：自己那一行的边框（平时绿色）和名字变红；观战：顶部"观战"两个字的参照图，观战和淘汰画面 0.98–1.00，其他画面 ≤ 0.21；冠军横幅 0.92，其他 ≤ 0.15；"返回大厅"按钮 0.98，其他 ≤ 0.24
- 成盒以后观战的人的头像也在左下角（往上移约 65）：认出他的传奇，是队友 = 队友还活着；不是 = 自己是小队最后一个被淘汰的（右上角最后的名次、RP 就是最终的）。样本：观战队友 0.93、观战对手 0.91
- 冠军局右上角最后的 RP 不是最终的（名次分结束后才加：右上角最后 +210，经验值页 +263）；倒地时全队被淘汰那局 −19 = 经验值页 −19
- 观战时右上角的剩余小队数会一直往下掉（录像：排名第 16，26 秒后显示剩 13 队），不能用来定名次
- 大厅段位那一行的文字常读错（"钻石 II"读成"钻石I""钻石ⅡI"），徽章下面的罗马数字单独读（放大 3 倍）27 张全对：段以徽章为准。整栏读一遍、按格式找段位和"868/1000 排位点数"，位置上下移动也不怕；"前 5 名排位点数：1571"没有斜杠，不会混进来
- 大厅左上角组队列表第一行是自己（旁边等级和左上角头像一致）；打开好友列表时那里是别人，要检查名字左边的位置

### 不同画面比例（16:10、4:3；2026-10-20 实战截图 `captures/aspect/`）

- 用户在 2560×1440 显示器上用 DX12 全屏 + Steam 启动项 `-w 2560 -h 1600`（16:10）、`-w 2560 -h 1920`（4:3）各打排位，用 `tools/frame_capture.py` 每秒截一张：
  - **DX12 的"全屏"不切换显示器分辨率**：游戏按启动项的分辨率画，再压扁铺满 2560×1440，没有黑边。截图一直是 2560×1440，看尺寸分不出游戏用的是哪种比例。所以要读 Apex 的视频设置文件（`Saved Games\Respawn\Apex\local\videoconfig.txt`，2026-10-20 用户决定，见 `game_aspect.py`）：全屏时 `setting.fullscreen` 是 1（`setting.nowindowborder` 也是 1），`setting.defaultres` × `setting.defaultresheight` 就是游戏用的分辨率。玩家常用的拉伸做法就是改这个文件或启动项
  - 只在无边框窗口里把启动项写成 1920×1200 时，窗口和显示模式都还是 2560×1440（拉伸在无边框窗口下不生效）。无边框窗口时文件里的分辨率不一定在用，所以只在全屏时用它，否则按截图的比例
  - 16:10 原生显示器（朋友的情况）截图就是 1920×1200，和这批截图还原成 16:10 是同一种摆法
- **摆法**：比 16:9 窄时，界面**按宽度缩放**（和 16:9 一样宽），上下多出一截（基准像素：16:10 多 120，4:3 多 360）。每块界面贴哪条边不一样，两种比例规律相同：
  - 贴上边：右上角（剩余小队、击杀那一行、伤害、RP）、顶部观战标签、淘汰画面"排名第 X"（虽然在屏幕中间）、开局横幅、总结页顶部横幅和右上角名次 / 小队总击杀、经验值页上半部分（本局 RP、段内进度、下一段位）、大厅左上角玩家名
  - 居中：总结页三张卡片（名字、击杀 / 助攻 / 击倒、伤害……、ID）
  - 贴下边：左下角自己和队友（头像、名字、倒地变红）、经验值页下半部分（三个合计和明细）、右下角"返回大厅"按钮
  - 大厅左下角段位栏：往下移了多出高度的 0.875（16:10）/ 0.87（4:3），取 0.87
  - 写在 `config/` 每个区域旁边的 `anchor`（top / center / bottom / 0–1 的数），换算在 `layout.py`；16:9 时和以前逐像素一样
- 结果：两种比例下画面全部认得出（当作 16:9 时一个都认不出），总结页、经验值页、大厅、淘汰画面、对局中读数全对；整局重放 16:10 一局、4:3 两局，存下的每一局和经验值页、大厅前后之差都对得上（`tests/test_aspect.py`）
- 压扁过的截图（4:3 时竖着压到 0.75）照样读得准：裁小块时横竖各自放大回基准尺寸
- 观战时右上角整块往下移（16:10 约 64），不过观战时不读右上角
- 还没见过：16:10、4:3 下的冠军横幅（先当作和淘汰画面一样贴上边）；21:9 等更宽的画面（照旧横竖各自拉伸，没校准）

### 右下角手上的武器（2026-10-24 用户在靶场截的 2560×1440 PNG + 一局实战 JPG，加上 16:10、4:3 那两局）

- 武器栏：手上那把的**大图标是白色**，武器栏底色是弹药颜色。下面一行两把武器的名字：手上那把底色亮、名字白；另一把底色暗、名字发灰，旁边有"R"提示（头上一个亮橙色小三角）。只有一把武器时（放大招、只拿着一把）只有一个名字
- 换枪的瞬间名字先换，图标还在播动画，两者对不上零点几秒；拾取时图标有动画（只有一两张）
- 双持（莫桑比克、P2020）显示两个图标；单拿时提示"找到第二把……"，第二把画成空心轮廓。单把的参照图在双持的图标里滑着也认得出
- 图标那块（基准 x 1530–1726、y 960–1024）里还有别的白色东西：上面的提示文字（"需要 1 个碎片手雷"）、下面一排配件格、"+"和弹药小图标（会碰到手枪的握把，连成一块，所以这两块挖掉不看）、三位数弹药（塞拉 135）的第一位、亮背景从武器栏上沿透过来
- 16:10、4:3 拉伸过的画面和 JPG 截图里图标常常只剩轮廓（中间那层浅灰没过白色门槛）：比之前把参照图和截图都轻轻模糊（3×3），实心的参照图也对得上

## 游戏画面特征（中文界面）

- **总结页**：三张队员卡片，**自己的卡片永远在中间**。卡片上有击杀/助攻/击倒（如 `5/7/7`）、造成伤害（带千位逗号，如 `1,727`）、生存时间（如 `16:03`）、给予急救次数、给予重生次数。右上角有小队排名（"第 6"）和小队总击杀。顶部横幅为"全军覆没"；拿冠军时是"捍卫者"，标签是"总结 | 经验值 | 通行证"
  - **名次和小队总击杀会晚 1–2 秒滑进来**，每次切到总结页都会重播这个动画。所以"连续两次读数相同"不够，要等名次等关键项都读到
  - **第 2 名有时没有总结页**：没有时顶部只有"死亡回放 | 经验值 | 通行证"，只能从经验值页（名次、击杀、助攻、RP、段位）和对局中右上角（击杀、助攻、老板分、伤害）记录。冠军有总结页
- **死亡后的画面**（淘汰名次、观战、总结、经验值）顶部都有"实况 | 总结"标签栏，位置固定。但**自己先成盒、队友还活着时也有**，所以它只说明"自己出局了"。小队结束了的标志是右下角的"(B) 返回大厅"按钮（淘汰画面、全队被淘汰后观战对手、总结页、经验值页都有；观战还活着的队友时没有，那时右上角是"等待重生中"、底部是"下一个队友""标记最近的重生信标"）
- **名次出现在三处**：淘汰画面"排名第 X"、总结页"小队排名 第 X"、经验值页"定级 第 X"，可以互相核对
- **经验值页（RP）**：要手动切换（LB / RB）才能看到。顶部数字有滚动动画（读到 -7 时动画还没结束，按明细算最终应为 -10）。明细（击杀、助攻、参与、击杀上限调整、挑战者、前 5 名连胜、定级）在动画进行中就已经显示
  - 最终画面列出三个合计：战斗、奖励、定级（定级里已含"参赛花费 −65"），**三个合计相加 = 本局 RP 变化**（如 8 + 0 − 60 = −52，130 + 16 + 35 = +181）。动画播完前"参赛花费"那行还没出现，要读最后一帧。这一页还显示段位徽章、段内进度和"下一段位：钻石 I"，每局都能读到段位
  - 这里的击杀 / 助攻是"计入排位点数"的次数：同一名玩家被击杀两次只算一次，所以可能比总结页少（3 杀 → 计分 2 杀）。不能用它覆盖总结页
- **段内进度能串起来对账**：一晚上 942 → 939 → 967 → ? → 895 → 913 → 升段 94 → 69 → 9 → 掉段 964，每步差值都等于那局 RP；没进经验值页的那局用前后进度相减算出 −55
- **对局中右上角**：剩余小队数 / 玩家数、击杀 / 助攻 / 老板分（参与分：队友击杀、自己完全没参与；和总结页的"击倒"不是一回事）、伤害、段位徽章和本局实时 RP。击倒不算助攻，要等对手成盒才算。**观战时显示的是被观战者的数据，不是自己的**
- **对局中左下角**：最下面一行是自己（头像、名字、护甲和血条），上面两行是队友（小头像、名字）。倒地时自己那一行变红，下方出现击倒护盾条；队友倒地时那一行变红色斜纹、右边有红色"+"。队友标点时最上面会临时弹出一张"头像 + 名字"的卡片
- **拿冠军那一刻**：屏幕中间"你已成为 捍卫者"，右上角和左下角整个界面都消失
- **开局画面**：左上角横幅"排位赛 - 空降地点"，下面一行是地图名（如"奥林匹斯"）。**横幅后半句看段位**（用户 2026-10-20 说明）：固定跳点制的局写"排位赛 - 空降地点"，跳伞制的局只写"排位赛"。实测：钻石 II 的局（10-16 世界尽头、10-18 残月）有"- 空降地点"，白金 III 的局（10-20 奥林匹斯 3 局）没有。以前靠"空降地点"认开局画面，跳伞制的局一局都认不出；2026-10-20 改成认两种都有的"排位赛"三个字（用户决定两种都要认）：全部截图里，开局横幅相似度最低 0.67（16:10、4:3 的短横幅 0.98），其他画面最高 0.24；选传奇时左上角的小字"排位赛"、大厅左下角的模式框都不在检查区域里。从加载画面、等待玩家到选空降点一直显示。Discord / Steam 的好友列表悬浮窗会盖住这一块，所以要读多帧
- **大厅**：左下角显示段位 + 段内进度（如"钻石 I，48/1000 排位点数"）以及模式和地图（如"排位赛 / 三人赛 / 世界尽头"）。没有单一的"总 RP"数字。"前 5 名排位点数"是活动分数，不需要。组队或有活动文字时，段位那一栏的位置会往下移
- **账号**：游戏里看不到自己的固定 ID。大厅左下角的 `SID：2:1019819:11662379:<UUID>` 不是账号编号（UUID 每次登录都变，前半串随游戏版本变）；总结页卡片下面的"ID：0160…"是固定的，但只显示队友的，自己那张是空的。所以按名字区分账号（`player_name.py`），改名后合并
- **干扰**：游戏字幕框会遮挡画面中下部；录像右下角的 outplayed 水印只在录像里有
- **每局结束后常常不回大厅**：结算后常常直接进入下一局（重新排队）。一局的分界是下一次开局画面，或者回到大厅
