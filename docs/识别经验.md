# 识别经验：实测结论和游戏画面特征

改模型（识别逻辑、`config/`）时读这份。流程本身见 [模型流程.drawio](模型流程.drawio)，规则为什么这样定见 [对局全流程图.md](对局全流程图.md)。

坐标统一写在 **1920×1080 基准分辨率**下（`config/*.json`），运行时按实际分辨率缩放。所有区域、参照图、门槛都必须用真实截图校准。

## 实测结论

### 引擎（OCR）怎么用（最小 demo）

- 只裁小块识别，不识别整张图：整张图 1.83 秒、内存峰值 511 MB；7 个小块 0.22 秒、峰值 154 MB
- 识别小块时要设 `Det.limit_type = "max"`：默认规则会把短边放大到 736 像素，小块会被放大十几倍
- 橙色数字转灰度后再识别：彩色时 `5/7/7` 会被读成 `5/717`
- 格式校验要严格：某些预处理下 `5/7/7` 被读成 `51717`，置信度却高达 0.98
- 如果以后 OCR 准确率不够：可以考虑用数字模板匹配读数字（字体固定，快且省内存）

### 画面判断和内存

- 判断画面分两步（`screens.py`）：先把检查区域和参照图（`config/templates/`，只截关键字本身）比较文字轮廓，像了才跑识别。参照图在区域里滑动比较，能容忍关键字前面的数字、模式名长短不同造成的左右偏移。120 张截图：目标画面相似度 ≥ 0.75，其他画面 ≤ 0.19，门槛 0.35；判断结果和只用识别时完全一样
- 游戏画面上每次检查从约 215 毫秒（4 次识别）降到约 1.5 毫秒（0 次识别）。贵在"开局画面"那块：对局中左上角有很多界面文字，一次识别就要 185 毫秒
- 内存峰值的来源：识别引擎会把细长的一行字（如 464×14）拉到约 1600 像素宽再识别，一次多占约 60 MB、花 0.5 秒。所以不要让识别引擎看游戏画面。关掉 onnxruntime 的 `enable_mem_pattern` 没有用
- 没有按"大厅 / 对局中 / 阵亡 / 结算"状态限制检查哪些画面：外观检查已经很便宜，再按状态筛选省不了多少，反而可能因为状态猜错而漏掉画面

### 对局中和大厅（1080p 录像截图 `captures/samples/` + 27 张大厅截图 + 实战）

- 认得出自己的传奇 = 这一张是自己的界面：观战时左下角是被观战的人、整块往上移约 60，认不出，所以右上角只在认得出自己传奇的截图上存
- 队友的头像和自己的是同一套美术图，缩小到约 0.65 倍：传奇参照图缩小后就能认（相似度 0.80–0.83，第二像 ≤ 0.36），不用新做参照图
- 右上角每一项要单独裁一小块读（放大 3 倍、四周加边）：整块一起读时单独一个"1"会漏掉；伤害前面的图标会被读成"3""1"，要先用参照图找到图标（它和数字一起靠右对齐，位置会变），只读右边
- 右上角击杀 / 助攻 / 老板分那一行全是 0 时不显示，背后的画面会被读出一个数（实战：老板分读成 7）；那一行显示着时数字又可能读不出来（读成 0）。所以那一行看最左边的骷髅图标：图标不在 = 全是 0，图标在、数字读不出来 = 留空。还没造成伤害时伤害那一格也不显示（看伤害图标）。没显示算 0 的前提：剩余小队数或 RP 读到过，证明区域没错
- 倒地：自己那一行的边框（平时绿色）和名字变红；观战：顶部"观战"两个字的参照图，观战和淘汰画面 0.98–1.00，其他画面 ≤ 0.21；冠军横幅 0.92，其他 ≤ 0.15；"返回大厅"按钮 0.98，其他 ≤ 0.24
- 成盒以后观战的人的头像也在左下角（往上移约 65）：认出他的传奇，是队友 = 队友还活着；不是 = 自己是小队最后一个被淘汰的（右上角最后的名次、RP 就是最终的）。样本：观战队友 0.93、观战对手 0.91
- 冠军局右上角最后的 RP 不是最终的（名次分结束后才加：右上角最后 +210，经验值页 +263）；倒地时全队被淘汰那局 −19 = 经验值页 −19
- 观战时右上角的剩余小队数会一直往下掉（录像：排名第 16，26 秒后显示剩 13 队），不能用来定名次
- 大厅段位那一行的文字常读错（"钻石 II"读成"钻石I""钻石ⅡI"），徽章下面的罗马数字单独读（放大 3 倍）27 张全对：段以徽章为准。整栏读一遍、按格式找段位和"868/1000 排位点数"，位置上下移动也不怕；"前 5 名排位点数：1571"没有斜杠，不会混进来
- 大厅左上角组队列表第一行是自己（旁边等级和左上角头像一致）；打开好友列表时那里是别人，要检查名字左边的位置

## 游戏画面特征（中文界面）

- **总结页**：三张队员卡片，**自己的卡片永远在中间**。卡片上有击杀/助攻/击倒（如 `5/7/7`）、造成伤害（带千位逗号，如 `1,727`）、生存时间（如 `16:03`）、给予急救次数、给予重生次数。右上角有小队排名（"第 6"）和小队总击杀。顶部横幅为"全军覆没"；拿冠军时是"捍卫者"，标签是"总结 | 经验值 | 通行证"
  - **名次和小队总击杀会晚 1–2 秒滑进来**，每次切到总结页都会重播这个动画。所以"连续两次读数相同"不够，要等名次等关键项都读到
  - **第 2 名有时没有总结页**：没有时顶部只有"死亡回放 | 经验值 | 通行证"，只能从经验值页（名次、击杀、助攻、RP、段位）和对局中右上角（击杀、助攻、老板分、伤害）记录。冠军有总结页
- **死亡后的画面**（淘汰名次、观战、总结、经验值）顶部都有"实况 | 总结"标签栏，位置固定。但**自己先成盒、队友还活着时也有**，所以它只说明"自己出局了"。小队结束了的标志是右下角的"(B) 返回大厅"按钮（淘汰画面、全队被淘汰后观战对手、总结页、经验值页都有；观战还活着的队友时没有，那时右上角是"等待重生中"、底部是"下一个队友""标记最近的重生信标"）
- **名次出现在三处**：淘汰画面"排名第 X"、总结页"小队排名 第 X"、经验值页"定级 第 X"，可以互相核对
- **经验值页（RP）**：要手动切换（LB / RB）才能看到。顶部数字有滚动动画（读到 -7 时动画还没结束，按明细算最终应为 -10）。明细（击杀、助攻、参与、击杀上限调整、挑战者、前 5 名连胜、定级）在动画进行中就已经显示
  - 最终画面列出三个合计：战斗、奖励、定级（定级里已含"参赛花费 −65"），**三个合计相加 = 本局 RP 变化**（如 8 + 0 − 60 = −52，130 + 16 + 35 = +181）。动画播完前"参赛花费"那行还没出现，要读最后一帧。这一页还显示段位徽章、段内进度和"下一段位：钻石 I"，每局都能读到段位
  - 这里的击杀 / 助攻是"计入排位点数"的次数：同一名玩家被击杀两次只算一次，所以可能比总结页少（3 杀 → 计分 2 杀）。不能用它覆盖总结页
- **段内进度能串起来对账**：一晚上 942 → 939 → 967 → ? → 895 → 913 → 升段 94 → 69 → 9 → 掉段 964，每步差值都等于那局 RP；没进经验值页的那局用前后进度相减算出 −55
- **对局中右上角**：剩余小队数 / 玩家数、击杀 / 助攻 / 老板分（参与分：队友击杀、自己完全没参与；和总结页的"击倒"不是一回事）、伤害、段位徽章和本局实时 RP。击倒不算助攻，要等对手成盒才算。**观战时显示的是被观战者的数据，不是自己的**
- **对局中左下角**：最下面一行是自己（头像、名字、护甲和血条），上面两行是队友（小头像、名字）。倒地时自己那一行变红，下方出现击倒护盾条；队友倒地时那一行变红色斜纹、右边有红色"+"。队友标点时最上面会临时弹出一张"头像 + 名字"的卡片
- **拿冠军那一刻**：屏幕中间"你已成为 捍卫者"，右上角和左下角整个界面都消失
- **开局画面**：左上角横幅"排位赛 - 空降地点"，下面一行是地图名（如"奥林匹斯"）。从加载画面、等待玩家到选空降点一直显示。Discord / Steam 的好友列表悬浮窗会盖住这一块，所以要读多帧
- **大厅**：左下角显示段位 + 段内进度（如"钻石 I，48/1000 排位点数"）以及模式和地图（如"排位赛 / 三人赛 / 世界尽头"）。没有单一的"总 RP"数字。"前 5 名排位点数"是活动分数，不需要。组队或有活动文字时，段位那一栏的位置会往下移
- **账号**：游戏里看不到自己的固定 ID。大厅左下角的 `SID：2:1019819:11662379:<UUID>` 不是账号编号（UUID 每次登录都变，前半串随游戏版本变）；总结页卡片下面的"ID：0160…"是固定的，但只显示队友的，自己那张是空的。所以按名字区分账号（`player_name.py`），改名后合并
- **干扰**：游戏字幕框会遮挡画面中下部；录像右下角的 outplayed 水印只在录像里有
- **每局结束后常常不回大厅**：结算后常常直接进入下一局（重新排队）。一局的分界是下一次开局画面，或者回到大厅
