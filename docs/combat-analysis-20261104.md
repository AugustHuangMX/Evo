# Apex 战斗表现与多维分析（2026-11-04）

## 游戏含义与设计依据

本页将击杀、助攻、击倒作为并列信号展示，避免将发生在同一名敌人身上的击倒、后续击杀累加为“综合贡献”。K+A 只表示本人的击杀加助攻计数；它不是 K/D、独立伤害目标数或整局综合评分。

核对的官方资料：

- [EA 排位说明](https://help.ea.com/en/articles/apex-legends/ranked/)：个人击杀与助攻会影响淘汰收益，名次、奖金与赛季规则也影响 RP。因此使用实际记录的 RP 按 K+A 和名次分组，不反推、预测或固定编码游戏计分规则。
- [EA 游戏术语说明](https://help.ea.com/en/articles/apex-legends/terms-guide/)：击倒状态与最终淘汰存在区别。仅凭结算总数不能识别每次击倒后来是否成为击杀，也无法区分复活、重生及各次交火，故不生成“击倒转化率”。

以上是对指标选择的设计依据；软件的派生指标及分组边界由本页定义，不作为 EA 官方评分指标。

## 五种分析视图

1. **战斗贡献**：击杀 / 助攻 / 击倒的场均、合计和有效局数常驻顶部。三条走势使用共同次数轴，颜色与实线 / 虚线 / 点线结合，可独立显示或隐藏；支持逐局、自然日均值、鼠标和键盘选点。下方补充输出节奏、救起、重生及小队占比。
2. **表现走势**：17 项原始或派生指标可切换，缺失处断线；逐日时保留各指标自己的有效分母。
3. **分组比较**：传奇、地图、模式、记录段位可切换；默认多指标矩阵，包含 14 项指标及局数，共 16 列。每个单元格标注有效 / 总局数，可按列排序、搜索；小于 5 局的分组提示小样本。颜色在每列内比较数值（RP 按绝对值，正负由数值表达），不评价整体能力。仍可关闭矩阵使用原单指标比较。
4. **多维关系**：横轴、纵轴、气泡面积、颜色四种编码，附五个预设：伤害×击倒、击倒×K+A、存活×K+A、K+A×RP、小队贡献。气泡面积随选定的非负指标变化，零值保留最小点；RP 有正负，不能用于气泡面积。颜色可编码名次区间、RP 正负、传奇。所有所选编码完整的局才绘点，显示实际有效局数。超过 600 点时等距抽样，仅绘点抽样，统计及导出仍使用全部对局。
5. **名次与 RP**：K+A 的 0 / 1–2 / 3–5 / 6+ 与冠军 / 2–5 / 6–10 / 11–20 名交叉，显示实际 RP、伤害或击倒的均值。每格有有效 / 所含局数，点击查看具体对局；超过 20 局可继续展开。不同段位、模式和赛季的混合统计不作因果解读。

## 指标与有效性

九个原始指标：击杀、助攻、击倒、伤害、名次、存活秒数、RP、救起队友、重生队友。新增八个指标如下：

| 指标 | 单局公式 | 有效性约束 |
| --- | --- | --- |
| K+A | 击杀 + 助攻 | 两项都有效；不含击倒 |
| 小队击杀 | 直接记录的小队击杀 | 缺失时仅用本人和两名完整、不重复的总结页队友击杀合计补足 |
| 每存活分钟伤害 | 伤害 ÷ 存活秒数 × 60 | 伤害有效、存活 > 0 |
| 每存活10分钟 K+A | K+A ÷ 存活秒数 × 600 | K+A 有效、存活 > 0 |
| 每存活10分钟击倒 | 击倒 ÷ 存活秒数 × 600 | 击倒有效、存活 > 0 |
| 击杀参与率 | (击杀 + 助攻) ÷ 小队击杀 × 100% | 小队击杀 > 0，且 K+A 不大于小队击杀 |
| 小队击杀占比 | 本人击杀 ÷ 小队击杀 × 100% | 分母 > 0，本人击杀不大于分母 |
| 小队伤害占比 | 本人伤害 ÷ 三人伤害合计 × 100% | 本人和两名总结页队友的伤害都有效，不重复，分母 > 0 |

全部平均占比和时间归一化指标采用**单局比值的算术均值**，不是总分子的总分母之比。短局的每分钟值容易波动，应结合原始次数、存活时间和样本数观察；它们不是交火时 DPS。

经验值页的击杀和助攻计分次数都不作为真实战斗次数。字段缺失、无效数、零分母、矛盾占比保留为空，不作零、不截断成 100%；非排位 RP 不参与统计，非排位也不沿用历史段位。待确认局仍保留并标记；不把整局数量当作每个派生指标的分母。没有死亡次数与逐次战斗事件，因此没有 K/D 或转化率；也没有自行加权的综合分数。

## 数据与交付

- 计算只使用已记录字段及现有队友数据；不采集新数据、不增加上传字段、不修改数据库结构。图表数据没有队友姓名或 ID。
- 图表继续使用原生 SVG，深浅主题共用同一布局；三种战斗颜色属于数据编码，页面强调色仍沿用现有主题。
- CSV 导出包含全部 17 项指标，缺失留空；明细继续定位到对应历史对局分页。
- 本地预览使用已有真实战绩的只读快照，没有重新生成演示记录。
