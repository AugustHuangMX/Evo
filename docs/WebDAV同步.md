# WebDAV 同步：设计、升级与兼容性

本功能让多台 Windows 电脑使用用户自己的 WebDAV 服务合并 Evo 战绩。设置入口在“设置 → WebDAV 同步”，包括连接测试、手动同步、自动同步、可选截图同步和断开。通用安装首次保存配置后仍默认关闭自动同步与截图同步，用户主动开启才传输对应数据。服务器、账号、密码和运行数据不随源码或提交分发。

## 对原有设计的改动范围

沿用 SQLite、现有表和 `match_id` 关联、Flask 面板、托盘线程及 PyInstaller 文件夹构建。没有替换数据库或数据访问层，没有重建业务表，也没有改变 CSV 的业务列、采集/OCR、校准规则或已有账号分组。同步附加信息与业务数据分开保存。

| 数据库版本 | 新增内容 | 既有数据的处理 |
|---|---|---|
| 8 → 9 | `matches` / `lobby_readings` 追加 `sync_uid`、`sync_updated`；稳定 UID 的唯一索引；`sync_tombstones` | 业务字段、原 ID、关联关系、NULL 和本机截图路径保留 |
| 9 → 10 | `sync_revisions`、`sync_conflicts`、`sync_media` | 分别保存逻辑版本及内容指纹、部分并发冲突副本和截图引用，不改业务列 |

`APP_VERSION` 保持 `0.4.0`，满足现有更新器的数字版本约定；窗口另外显示 `WebDAV beta 3`。这是贡献分支的构建标识，不宣称上游已正式发布此功能。

## 数据库升级、回退与未来版本

1. 打开已有库时先检查 schema。高于 10 的未知未来版本会拒绝打开写入，不降低版本号。
2. schema 低于 10 且存在业务表时，先用 SQLite 在线备份生成 `data/evo.db.before-v<旧版>-to-v10-<随机号>.bak`，包含 WAL 中已经提交的事务，并执行完整性校验。备份失败则停止升级。
3. 迁移取得写锁后重新读取版本，在同一事务内逐步升级并设置 `user_version`；中途失败会回滚迁移。数据库备份和后续迁移是两个步骤，备份之后的新写入不属于此前备份的时间点。
4. 已验证历史 schema 1–9 升级、迁移故障回滚、WAL 备份与未来 schema 拒绝写入。也使用作者发布的原版 0.4.0 二进制读写追加后的 schema 10，再切回新版检测旧版编辑。
5. 旧版没有同步元信息写入逻辑。新版在同步时以内容指纹识别业务变化并递增逻辑版本；对已有同步版本但被旧版删除的记录补墓碑。旧版尚未同步过、也未建立稳定身份就被删除的记录，没有足够信息传播删除。

“原版 0.4.0 本地读写兼容”不代表它具备 WebDAV 功能，也不代表未知未来版本兼容。不要让多个版本同时记录同一个目录。回退前应退出 Evo 并备份当前完整数据目录；恢复升级前备份会丢失该备份之后的新记录，不能把它当作无损逆向迁移。未来上游增加 schema 时，需重新评估迁移编号、表结构和同步协议。

## 同步协议与冲突规则

- 每台电脑和数据目录各写自己的 `evo-v2-<16 位编号>.json.gz`。先下载各设备快照并合并，再上传本机快照；不依赖服务端 `If-Match` / `If-None-Match` 条件写入，适配忽略这些条件的服务端。设备同时运行时可能需要下一轮同步才能看到对方最新内容。
- 每局带稳定 UID；旧数据首次同步时按既有内容生成，以便相同数据副本去重。新记录使用随机 UID。首次建立身份之前已分别修改的副本，不保证仍能自动识别成同一局。
- 一局的业务字段、队友、来源读数和武器记录一起合并，另同步大厅读数及账号名。账号名会补充，已有本机账号分组优先，不远程重排账号。
- 每条记录的逻辑计数器在检测到内容变化时递增；收到远端版本后，后续本地编辑从收到的版本继续递增。UTC 时间仅作审计，不参与冲突排序。
- 离线并发修改按 `(计数器, 设备号, 内容哈希)` 固定顺序选取整条记录，保证收敛。它不能恢复两次离线编辑的真实物理先后，也不逐字段合并。同计数器、不同设备时的落选内容保留在 `sync_conflicts`；没有冲突浏览或一键恢复界面，不承诺保留所有不同计数器的并发落选版本。
- 删除通过墓碑传播且优先于记录，不因旧快照再次出现而复活；目前不自动清理墓碑。清空数据会记录同步删除，开启同步时确认框会提醒跨设备影响。
- 协议 2 使用不同文件前缀，忽略旧实验协议 1 的文件。参与同一组同步的电脑应全部使用协议 2；不会自动导入旧实验快照。
- 合并先取得 SQLite 写锁，导出使用一致事务；缓存按服务器、用户名和目录隔离。ETag 等可靠元数据未变时复用缓存，本机快照内容未变则不重复上传。

## 凭据与传输边界

`settings.json` 只保存 `password_dpapi` 密文，使用 Windows 当前用户 DPAPI，不在二进制内放置解密密钥。读取旧明文配置时原子转换并移除明文键。换电脑、换 Windows 用户或密文损坏时要求重新填写密码，不静默使用空密码联网。DPAPI 保护磁盘上的凭据，不防范已能以同一 Windows 用户身份运行的恶意程序。

更换服务器或用户名需要重新输入密码；拒绝跨服务器和 HTTPS 降级重定向。配置仍允许用户显式填写 HTTP，因此应使用 HTTPS 服务。同步数据自身由用户的 WebDAV 服务保存，不经过开发者服务器，也没有额外的端到端内容加密。

设置读写使用进程内可重入锁，写临时文件后 fsync 并原子替换，降低后台同步与面板同时写设置的覆盖和文件共享冲突风险；不提供多个独立进程同时修改同一设置文件的通用协调机制。

## 可选截图同步

默认关闭，开启后传输战绩关联截图。图片按 SHA-256 放在 `<同步目录>/screenshots/<哈希>.jpg/png`，快照只包含哈希、大小和格式，远端不能指定本机路径。已有可用的本机截图保留，缺失截图下载到 `captures/webdav/`。下载验证哈希、大小、图片格式及解码结构；单张最多 20 MB、4000 万像素。失败会报告，但不阻断正常战绩合并。

关闭后停止图片传输，不删除云端已有图片。删除战绩会传播删除该战绩，但目前不会自动删除云端无引用图片；没有远端图片垃圾回收。图片可能包含玩家、队友的名字和 ID，甚至屏幕中的其他内容。设置页说明这一影响；截图计数包含原有本机记录和同步下载目录。

## 自动同步、构建与验证

主动开启自动同步后，启动约 30 秒执行一次，之后每 30 分钟一次。面板开关可启动或停止等待中的同步线程，不影响检查更新等线程；已经发出的网络请求会完成。连接测试只在选定目录读写独立小测试文件。创建嵌套目录时兼容服务端因缺父目录返回的 409，逐层 MKCOL 后重新核验；普通 PROPFIND 的 409 仍作为错误报告。

无新增运行时第三方依赖。凭据使用 Python ctypes 调用系统 DPAPI，截图验证使用已有 Pillow。构建仍使用现有 PyInstaller，签名验证优先使用可用的 `pwsh`，否则使用 Windows PowerShell；保留 WebView2 引导程序的微软签名校验。打包排除当前 CPU ONNX 路径未使用的其他推理框架和模型工具，实际构建及 CPU OCR 初始化已验证，尚未覆盖所有电脑环境和第三方后端组合。

可重复运行：

```text
python tests/test_webdav_sync.py
python tests/test_sync_compatibility.py
python tests/run_all.py
```

迁移测试从 Git 的历史提交加载 storage，实现没有复制进生产代码；运行测试需要完整相关历史，浅克隆需先获取历史。专项测试为 WebDAV 79 项、迁移/DPAPI/截图 30 项。完整回归中缺少仓库未分发的截图样本时会跳过相应组，不能把跳过当成实战通过。

另外在授权真实数据副本和真实 WebDAV 服务上验证过：8 局与 5 局（其中 3 局重叠）合并为 10 局，全部业务字段及关联表一致；9 张截图逐张哈希一致；编辑、错误日期、删除传播、无变化缓存、空库恢复与启动自动同步。使用原生 Windows 窗口完成浏览、编辑、连接、同步与图片显示检查。模拟设备使用同一电脑的独立目录，尚未替代两台实体电脑长期使用、真实游戏采集与性能验收。

测试账户、密码、DPAPI 密文、真实数据库、玩家姓名/ID、截图、日志和本机安装配置不进入 Git 或 PR 附件。PR 仅提供不含用户数据的实现、文档和可重现测试。
