## 一局的阶段（按游戏里的顺序）

### 1. 大厅（已定）

现在的代码：只认出大厅，什么都不读。

改成：
- **读什么**：玩家名（左上角组队列表第一行；旁边的等级和左上角头像的等级一致，就是自己）、段位 + 段内分数（左下角，如"钻石 II，868 / 1000 排位点数"），按 `config/ranks.json` 换算成总分（钻石 II 868 = 14868）
- **读法**：进大厅后连续读，两次结果一样就算定下来，之后不再读，直到离开大厅（最多读 6 次）。截图频率不变
- **总分以大厅为准**（最高优先级）：总览页的段位卡片和走势图都按它来
- **校准每局 RP**：每局 RP 仍从经验值页读，用前后两次大厅读数核对：中间各局 RP 之和 = 两次大厅的差。只缺一局时用差值补上；对不上时这几局标"待确认"，总分仍以大厅为准
- 打完一局通常不回大厅，所以每次回大厅都要抓住，用来校准
- **难点**：
  - 组队、有活动文字时，段位那一栏会往下移：先找到"排位点数"这几个字，再读旁边的内容
  - "钻石 II"容易读成"钻石I"：用段位徽章下面的罗马数字、经验值页的段位互相核对
- 大厅最下面的 `SID：…` 不是账号 ID（每次登录都变），不用

### 2. 开局画面（不改）

读模式和地图，两项都读到就不再读。一进开局画面就给上一局收尾、让之前认出的传奇作废（一局的分界）。

### 3. 选角色界面（不改）

不识别、不读数，等同待机。玩家轮流选、画面复杂、信息量少；传奇照旧在跳伞后从左下角头像认。

### 4. 对局中（已定）

自己的传奇、玩家名：和现在一样（每 3 秒看一眼左下角头像，同一个传奇认出 2 次算数；认出的那一张读名字）。

新增：
- **队友的传奇和名字**：以对局中左下角为准，总结页用来核对（robustness check）
  - 只在**认出自己传奇的那一张**截图上认队友（证明左下角是自己的界面，不是在观战）
  - 传奇：和认自己一样，用现有的 28 张参照图，缩小到约 0.65 倍比对，不用引擎。同一个传奇认出 2 次算数，一局只认一次
  - 名字：在那一张上把名字那一条裁下来留在内存里，等结算时本来就要用引擎了再读（交火时不加载引擎，原则 3）
  - 和总结页按名字对上（名字里可能有游戏显示不了的字，如"□"，要按"很像"来比）。总结页另外提供 ID 和这一局的数据。对局中没读到的名字用总结页补；两边对不上时用对局中的，只在日志里记一笔
  - 读不到就留空，不因为队友标"待确认"
  - 双人赛只有 1 名队友；队友退出、掉线时有几个读几个
- **右上角数据**（为第 6 步准备）：每张截图把右上角那一小块裁下来，内容变了才存，在内存里只留最近 3 块，交火时不用引擎
- **手上的武器**（2026-10-24 用户决定，数据页"最常用武器"用）：只在认出自己传奇、而且没倒地的截图上看右下角手上那把的大图标（观战时右下角是被观战的人的武器，倒地时拿不了武器）
  - 比外观、不用引擎：图标挑出白色像素，和每把武器的参照图比（`weapons.py`，规则 `config/weapons.json`，参照图 `config/templates/weapons/` 由 `python tools/weapon_templates.py` 从靶场截图生成）；图标没变就不重新比
  - 算武器的：29 把枪，加上兰伯特的"塞拉"和万蒂奇的大招（显示成"万蒂奇的狙击枪"）；"手感卓越的刀刃"不算（正常对局里没有）。认不出的（打药、拿手雷、空手、没见过的东西）不计时
  - 每一段拿在手上的时间记下来（同一把武器隔 2 秒以上没看到算两段），一局结束时交给第 6 步，记进 `weapon_holds` 表；时间从这一局第一次拿到武器算起
  - 数据页只算第一次拿到武器 1 分钟以后的（不算落地后随手捡的，2026-10-22 用户决定）；每一段都存着，这个规则以后改了旧的局也能重算
- **截图频率**（2026-10-18 用户决定，先用来实测 CPU）：从开局画面起、到结算画面或回到大厅为止，每 0.3 秒一张；其他时候每 1 秒一张（config/hud.json 的 match_interval）

### 5. 倒地、成盒、观战（已定）

现在的代码：不专门认，当作对局中。

改成，对局中分三种状态：

| 状态 | 怎么认出 |
|---|---|
| 存活 | 平时的样子 |
| 倒地 | 左下角自己那一行变红（名字也变红），屏幕下方出现击倒护盾条 |
| 成盒（观战） | 顶部出现"实况 \| 总结"和"观战 \| 小队"两排标签，右上角有"等待重生中" |

- 倒地后被队友救起、成盒后被重生信标复活：都回到"存活"，继续记录，不停止
- 观战时右上角和左下角的主角都是**被观战的人**，不读右上角（左下角整块还会往上移约 60 像素）
- 现在版本没有金色击倒护盾，倒地不能自救

### 6. 一局结束：取"结算前最后一次"的数据（已定）

- **什么时候算结束**：出现淘汰画面、出现"你已成为 捍卫者"横幅、出现右下角的"返回大厅"按钮（2026-10-19 用户决定：小队已淘汰；"实况 | 总结"标签不够，自己先成盒、队友还活着时也有），或者自己成盒以后直接进了下一局
- 回头读第 4 步存下的右上角小块，取最后一次读到的：**击杀、助攻、老板分（参与分）、伤害、RP、剩余小队数**
- 第 4 步记下的每一段手上的武器一起交过去（一局结束时不用再认，已经认好了）
- 右上角没显示的项算 0（对局初期还没数据时就不显示；击倒不算助攻，要等对手成盒才算）。保险起见：某一项显示过、后来又不显示，就沿用最后一次读到的值
- 击杀 / 助攻 / 老板分那一行（2026-10-20）：先找每一项前面的图标再读数字（这一行的数字位置随位数变）。这一行显示着、但某一项的数字读不出来，或者老板分的图标不在（用户说过老板分不是每次都有）：这一项留空，不当作 0
- 拿冠军那一刻，横幅出现时右上角和左下角整个界面都消失，所以要用横幅出现**之前**的截图

| 情景 | 用哪些数据 |
|---|---|
| 自己是小队最后一个被淘汰；或者自己倒地时全队被淘汰 | 最后一次读数就是最终数据，名次（剩余小队数）、RP 也算。怎么知道自己是最后一个：成盒以后观战的是对手、不是队友（队友还活着时游戏默认观战队友；2026-10-18 实战 #45 就是这种，之前被当成了"先成盒"） |
| 成盒后直接进了下一局（队长重新匹配，没出现结算画面） | 这一局已经打完了，不是掉线，不用确认；数据同上（按自己是不是最后一个） |
| 冠军 | 横幅出现前最后一次读数：击杀、助攻、老板分、伤害是最终的；**RP 不是**（冠军的名次分比赛结束后才加，2026-10-18 实战：右上角最后 +210，经验值页 +263），以经验值页为准，没有就等大厅校准 |
| 自己先成盒，队友后被淘汰（包括成盒后一直没被复活） | 击杀、助攻、老板分、伤害用成盒前的；这时的 RP 不可靠，以经验值页为准，没有就用大厅校准 |
| 成盒后提前回大厅 | 只有成盒前的数据；名次和 RP 用大厅校准（前后两次大厅读数，减去其他局的 RP，推出这一局） |
| 掉线、游戏崩溃（还活着就没了下文，或者停止记录） | 标"待确认" |
| 匹配模式 | 以后再做（右上角没有 RP） |

"阵亡瞬间的 RP 就是最终 RP"目前是推测：前几局要拿经验值页核对，确认后才把右上角的 RP 当作可靠来源。

### 7. 淘汰画面、总结页、经验值页、一局收尾（已定：基本不改）

用户：这几页相对稳定，用户停留够久时最好。用现在的代码读冠军总结页：认得出（相似度 0.94），击杀/助攻/击倒、伤害、生存时间、
急救、重生、小队总击杀、玩家名全部读对；名次那张截图里还在滑进来，代码会等它。跟着前面的决定补了几处：

- **冠军的总结页不等名次**（2026-10-21）：顶部是"捍卫者"、没有"第 X 名"，名次永远读不到。以前要等离开或等满 10 秒才存；现在其他数字连续两次一样、顶部是"捍卫者"就存（存下的数据一样，第 1 名照旧由冠军横幅补），"总结页读完了"的提示音也能响
- **"捍卫者"就是第 1 名**：拿冠军那一刻的横幅（"你已成为 捍卫者"）和冠军总结页顶部的"捍卫者"都记第 1 名（来源"冠军横幅"）。
  冠军有总结页（2026-10-18 样本），顶部横幅是"捍卫者"，标签是"总结 \| 经验值 \| 通行证"，卡片位置和平时一样
- **一局收尾合并新的来源**：对局中最后的读数、对局中认出的队友，按上面的优先级合并，按"比页面少算正常、比页面多标待确认"核对
- **少标待确认**：总结页停留太短、没读全时，缺的项能用别的来源补上，就不标
- **补上缺口**：经验值页一直没读全时，RP 先用对局中的（只限自己最后被淘汰；冠军不行，见第 6 步），再不行等大厅校准
- 回到大厅也算一局结束（大厅读数要在上一局记下以后才能校准）
- 以后再做：读经验值页明细里的"参与"那一行，核对老板分
- 结算画面右上角常出现"队长决定重新匹配"：这是总结页、经验值页常常看不到的原因之一，所以对局中的数据要足够可靠

### 8. 提示音（2026-10-21 用户决定，0.3.6 起）

群里用户的建议：一局结束时提醒去总结页，并告诉玩家每一页读到了没有。声音和开关见 `code/sounds.py`，什么时候响见 `live_collect.SoundCues`。

| 提示音 | 什么时候响 | 声音 |
|---|---|---|
| 对局结束 | 进入淘汰画面、冠军横幅、右下角"返回大厅"按钮（小队打完了），提醒去总结页 | 三个音从高往低，柔和 |
| 总结页读完了 | 总结页读全、存下这一局时（通常停 1–2 秒）；听到就可以离开 | 三个音同时轻轻响起再散开 |
| 经验值页 | 进入经验值页时 | 一个清脆的音 |

- **每局每一声最多一次**，下一局开局、回到大厅时重新算。总结页和经验值页来回切不重复响
- **对局结束什么时候不响**：这一局已经到过总结页或经验值页（比如从总结页切回"实况"又看到"返回大厅"）；自己先成盒、队友还活着（没有这几个画面）；提前回大厅、成盒后直接进了下一局
- **总结页什么时候不响**：停留太短没读全、等满 10 秒还没读全。没听到这一声，说明这一页没读好
- **经验值页只能"一进去就响"**：数字有动画，Evo 离开时才读最后一帧，没有"读完了"的那一刻（要做到得一直用引擎读，占 CPU）
- 默认开（用户决定），设置页能关、能试听；声音是自己合成的（`tools/make_sounds.py`，AGPL-3.0）。第一版"对局结束"往下跳五度、音色偏亮，用户觉得阴森，试听候选后换成现在的
- 上面"声音"一列是 Evo 默认的那套。2026-10-24 起设置页能换声音包（三声一起换）、用自己的音频文件、调音量（见 `code/sounds.py`）；什么时候响不变

### 9. 游戏语言（2026-10-24：英文、繁体已完成）

- 只做**识别游戏画面**的语言，Evo 窗口还是只有简体（2026-10-24 用户决定）
- 引擎不用换：PP-OCRv6 的字表里有繁体字和英文（"擊殺""傷害""排位賽""返回大廳""Kills"都在）
- 规则：简体是基准（`config/` 里的各个文件）；别的语言一个文件 `config/lang/<语言>.json`，只写和简体不一样的地方（关键字、地图名、段位名、区域……）；参照图放 `config/templates/<语言>/`，没有的照用简体的（传奇头像、右上角的图标不带文字）。见 `game_lang.py`
- 读出来的地图名、段位名、模式统一换成简体存，数据库和页面不用分语言
- 怎么知道游戏是哪种语言：不读游戏文件。设置页"游戏语言"（2026-10-24 用户要加）默认"自动识别"：还没认定时，每种画面按每种语言各比一次；认出一个画面、而且只有一种语言的关键字对得上，就认定是这种语言（游戏开着时换不了语言，每开一次游戏认一次），之后只按它比，不多花 CPU。几种语言的关键字都对得上时（比如繁体和简体的"排名第"一样），画面照样认出，语言先不认定（`screens.GameScreens`）。手动选了某种语言就只按它认；记录程序每 5 秒看一眼设置，改了几秒内生效
- 设置页列出简体中文、繁體中文、English，还没做好的显示但不能选，写"（还没做好）"（2026-10-24 用户决定）；`config/lang/` 里多出来的语言（社区加的）排在后面
- 原来写死在代码里的"排位点数"格式（经验值页、大厅、右上角 RP）挪进了 `config/`（`patterns`），别的语言各写各的
- **英文**（2026-10-24，`config/lang/en.json`，画面特征见 `docs/识别经验.md`"英文界面"）：位置和简体基本一样，换的是文字和参照图。英文和简体不同的几处做法：
  - 同一个画面有几种样子时（排位横幅"RANKED"、匹配横幅"TRIOS"），各用一张参照图，`as` 写成同一个画面，认出来以后一样处理
  - 大厅靠左下角的模式框"RANKED / UNRANKED"认（匹配时也认得出，回大厅就能给这一局收尾）；只有排位时才有段位那一栏，匹配时连续 2 次什么都没读到就不读了（`give_up_blank_reads`）
  - 经验值页一行分成几段（"Kills 1 12 RP"），拼起来读（`join_lines`）；"O RP"当成 0
  - 比关键字时不管空格和大小写
- **繁体**（2026-10-24，`config/lang/zh-TW.json`，见 `docs/识别经验.md`"繁体中文界面"）：位置和简体一样，字是繁体，分数写"RP"（经验值页、大厅、右上角的读法和英文一样）；大厅的模式框排位"積分賽"、匹配"普通對戰"没有一样的字，匹配那种单独一张参照图（`lobby_pubs`，`as` 大厅）
- **匹配局**（英文、繁体；简体 2026-10-24 截到一局后加上）：开局横幅"TRIOS""三排""三人赛"记成匹配（pubs）；匹配大厅没有段位那一栏，简体靠左下角卡片的"未上榜"、繁体靠"普通對戰"认出（`lobby_pubs`，`as` 大厅），连续 2 次读不到段位就不读；匹配的经验值页（"Combat XP Total"）不当成排位的经验值页；没有 RP、段位；大厅校准不给匹配局补段位

## 数据来源和优先级（已定）

总原则：**总结页、经验值页读得清楚时以它们为准**，对局中的数据只用来验证。玩家很快跳过、页面没读到时，对局中的数据要可靠到可以直接用，不需要玩家确认。

| 数据 | 来源（从高到低） |
|---|---|
| 击杀、助攻 | 总结页 → 对局中最后读数 → 经验值页（计分次数，可能偏少） |
| 击倒 | 总结页 |
| 老板分（参与分，新增） | 对局中右上角第三个数；经验值页明细里的"参与"可以核对 |
| 伤害 | 总结页 → 对局中最后读数 |
| 生存时间、急救、重生 | 总结页 |
| 名次 | 总结页、经验值页、冠军横幅、淘汰画面互相核对，对不上标待确认；都没有时用对局中的剩余小队数（只用来补） |
| 每局 RP | 经验值页 → 对局中最后读数（只限自己最后被淘汰；冠军不用） → 大厅校准补算 |
| 总分、段位 | 大厅 → 经验值页 |
| 队友名字、传奇 | 对局中左下角 → 总结页（核对、补空） |
| 队友 ID 和这一局的数据 | 总结页 |

两边对不上时：
- 对局中的读数**比页面少**：正常（最后一秒的击杀、伤害没截到），以页面为准，不标
